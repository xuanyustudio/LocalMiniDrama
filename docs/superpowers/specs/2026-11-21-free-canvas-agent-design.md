# 自由画布与画布智能体设计

日期：2026-11-21  
状态：已定稿（待实现）

## 背景

现有 `/film/:id/canvas` 是一部剧的结构视图。节点由角色、场景、道具、集、剧本、分镜和媒体投影出来，坐标只记在 `metadata.canvas_layout`。助手抽屉按当前剧改表，不拥有画布。

自由画布是首页单独入口的另一张图。文档自己保存节点和连线。智能体只用命令改这张图，并跑通剧本、分镜、出图、出视频、配音和合成。要进列表、导出或旧画布时，由人点「落成项目」写成一部剧。

参考 dramaclaw 的 Freezone：图是正文，写入靠命令回执，付费步骤先确认。不复制其代码。现有 `/film/:id/canvas`、列表模式、按剧记忆的助手保持原样。现有「自由创作」单次表单不替换，入口维持收起。

## 决策摘要

| 决策 | 选择 |
|------|------|
| 入口 | 首页「自由画布」。列表 `/studio`，编辑 `/studio/:id` |
| 真源 | 画布文档。生成过程中不写剧表 |
| 旧画布 | 继续只读剧表 |
| 智能体 | 每块画布单独的 `canvas-assistant`，不复用剧助手的工具 |
| 对话 | 一块画布一段。`threadId` 为 `studio-<画布 id>`，记忆仍用 `data/agent.db` |
| 生成 | 文本、生图、生视频、配音、ffmpeg 合成都走现有服务 |
| 付费确认 | 出图、出视频、配音在点允许之前不调用厂商 |
| 落成 | 只有顶栏按钮。再落成更新同一部剧 |
| 删除节点 | 对话里点允许才执行 |

不做：360 全景、3D 世界、预演、HTML 作品、技能节点、视频拆解、宫格切分、矢量图、动图、多段对话、画布与剧表实时对账、把落成做成智能体命令。

## 数据

新表 `free_canvases`：

| 列 | 含义 |
|----|------|
| `id` | 主键 |
| `title` | 标题 |
| `revision` | 整数，每次成功写入加 1 |
| `aspect_ratio` | `9:16`（默认）、`16:9`、`1:1` |
| `materialized_drama_id` | 落成后的剧 id，未落成为空 |
| `document` | JSON：`viewport`、`nodes`、`edges` |
| `created_at` / `updated_at` | 时间 |

风格不放在画布列上，只放在风格节点里。`update_canvas` 只改标题和比例。

上传文件放在 `storage/free-canvases/<canvasId>/uploads/`。生图、生视频、配音、合成若由现有服务决定路径，节点记录返回的 `local_path` 和 url。

节点公共字段：`id`、`type`、`position`、`data`、`status`、`error`、`parent_id`。`status` 为 `idle`、`awaiting_confirm`、`running`、`succeeded`、`failed`。服务端生成 `id`。智能体不能写 `status`、`error`、生成记录 id、文件地址。

| 类型 | 可写字段 | 服务端字段 |
|------|----------|------------|
| `text` | `text` | 无 |
| `script` | `title`、`premise`、`text` | 无 |
| `character` | `name`、`prompt` | `generation_id`、`image_url`、`local_path` |
| `scene` | `name`、`prompt` | 同上 |
| `prop` | `name`、`prompt` | 同上 |
| `storyboard` | `shot_number`、`action`、`dialogue`、`prompt`、`duration` | 无。时长只允许 3、5、8、10，默认 5 |
| `upload` | 无。文件只能由上传接口写入 | `image_url`、`local_path`、`source_file_name` |
| `image` | `prompt`。可省略，运行时再取上游 | `aspect_ratio` 空则用画布比例；`generation_id`、`image_url`、`local_path` |
| `video` | `prompt`、`duration`。都可省略 | `generation_id`、`video_url`、`local_path` |
| `audio` | `text`、`voice_id`。都可省略 | `audio_url`、`local_path` |
| `compose` | 无 | `video_url`、`local_path` |
| `style` | `text` | 无 |
| `group` | `title` | 无。子节点用 `parent_id` |

落成之后，节点 `data.bound_id` 记下项目里的对应行 id。这个字段只由落成写入。

文本长度上限：剧本文本 20000，前提 2000，提示词 2000，动作 500，台词 300，节点显示名 80。

## 连线

边：`id`、`source`、`target`、`relation`。不允许成环。

| `relation` | 允许的起点 → 终点 |
|------------|-------------------|
| `prompt_for` | 文本或风格 → 剧本、分镜、图片、视频。剧本 → 分镜。分镜 → 图片或视频。一张图片最多一条来自分镜的 `prompt_for`。一个分镜最多一条来自剧本的入边 |
| `media_input_for` | 上传图 → 图片或视频。图片 → 视频。一条视频最多 9 条来自图片/上传图的 `media_input_for`（多参考图） |
| `context_for` | 角色、场景、道具 → 分镜或图片 |
| `composition_input_for` | 视频或配音 → 合成 |

没给坐标时，服务端把分镜排在剧本右侧并纵向展开，图片在对应分镜右侧，视频再往右，配音在视频下方，合成在链路最右。手拖后的坐标写进文档。

## 命令

除读取和 `select_nodes` 外，写命令都带调用方看到的 `revision`。不一致则整条拒绝，文档不变，响应里带上当前 `revision`。智能体先重新读取，再重试一次。

成功回执：`ok`、新 `revision`、新建节点的正式 id、改过的节点 id、一句中文摘要。失败回执：`ok: false` 和中文原因。界面按回执刷新。模型回复不改文档。

| 命令 | 作用 |
|------|------|
| `get_canvas` | 摘要：类型、状态、镜号、截断文本、连线、revision。不写文档 |
| `get_node` | 一个节点的全文 |
| `create_node` | 建一个节点。同一次 `apply_ops` 里可用临时 id |
| `add_next_node` | 从某节点加上下游并连线。未指定类型时：剧本→分镜，分镜→图片，图片→视频，视频→合成。文本、角色、场景、道具、上传图、配音、风格、编组、合成没有默认下一步，必须带上目标类型 |
| `update_node` | 只改该类型的可写字段 |
| `create_edge` / `delete_edges` | 连线、拆线。拆线不需要允许 |
| `move_nodes` | 改坐标 |
| `layout_nodes` | 按上面的默认规则重排指定节点；未指定则重排整张图 |
| `group_nodes` | 建编组并设置子节点的 `parent_id` |
| `select_nodes` | 不改文档、不增加 revision。经 SSE 让界面选中这些节点 |
| `update_canvas` | 改标题、比例 |
| `apply_ops` | 上面的创建、修改、连线、拆线、移动、排版、编组，一批最多 40 步，一次成功或一次失败，只加一个 revision。不能包含删除节点和运行 |
| `delete_nodes` | 删除节点及其连线。先点允许。删除编组只去掉组框，子节点留下；要连子节点一起删，必须在允许卡里列出子节点 |
| `run_node` | 见下一节 |

已经连有图片或视频的分镜，不能在同一批 `apply_ops` 里被拆掉再重建。要先走 `delete_nodes`。

用户在界面里打字、拖拽、上传，走同一套写入和版本检查。拖拽保存需要防抖，仍带 `revision`。

## 运行

`run_node` 可带多个同动作的节点 id。

| 节点 | 动作 | 执行 |
|------|------|------|
| 剧本 | `generate_text` | 立刻用默认文本模型，按前提、已有正文和本次补充写入 `text` |
| 剧本 | `split_storyboards` | 立刻用文本模型。该剧本还没有分镜才允许。返回后一次写入全部分镜和连线。超过 30 镜整次拒绝，一个节点都不建。模型失败同样不建节点 |
| 分镜 | `generate_text` | 立刻按上游剧本改这一镜的动作、台词、提示词 |
| 角色、场景、道具、图片 | `generate_image` | 点允许后走现有生图。不调用会写入角色表、场景表、道具表的那些函数 |
| 视频 | `generate_video` | 点允许后走现有视频生成。请求带拼好的提示词、时长、比例和上游图片地址，`drama_id` 与 `storyboard_id` 为空。现有入口若强制要求分镜 id，另加一条不写分镜表的入口，记录仍进现有视频表 |
| 配音 | `generate_audio` | 点允许后走现有 `ttsService.synthesize`。`voice_id` 为空时与列表模式不指定音色相同 |
| 合成 | `compose_video` | 立刻走现有 ffmpeg 合成。不调用厂商 |

文本、上传图、风格、编组没有运行动作。

同一块画布同时只有一张未确认的卡。已有卡时，新的出图、出视频、配音直接拒绝。允许之前不插入生成记录。服务端把这些节点写成 `awaiting_confirm` 并增加 `revision`，回执为 `{ ok: true, pending: true, revision, nodeIds, summary }`。刷新后，所有 `awaiting_confirm` 节点重新合成这一张卡。拒绝则智能体收到「用户取消了这次生成」，节点回到 `idle`。允许后节点为 `running`，并记下任务 id。未决的删节点审批按现有剧助手的未决审批保存，刷新后仍可点允许或拒绝。

运行时由服务端拼提示词，把实际发出的字符串写回节点：

- 图片：节点自己的 `prompt`，没有就用上游分镜的 `prompt`，再加上 `context_for` 的角色、场景、道具。`prompt_for` 进来的风格节点按节点 id 升序接在后面。视频拼提示词时同样接上这些风格词。
- 视频：节点自己的 `prompt` 和 `duration`，没有就用分镜的。有图片入边则把该图作为画面输入。
- 配音：节点自己的 `text`，没有就用上游分镜台词。
- 合成：按分镜镜号，再按连线顺序。配音有连线就混入。任一视频没有文件，或本机没有 ffmpeg，合成节点为 `failed`，`error` 写明镜头或缺少 ffmpeg。

任务结束由后端写回节点并增加 `revision`。写回时按当前 revision 比较，冲突则重读再写，避免盖掉手拖或命令。页面关闭也会写完。智能体用 `get_node` 看结果。

缺文本、生图、生视频或配音配置时，不改文档内容，错误为「请先在 AI 配置里添加对应模型」。付费失败不自动重试。

助手初始化失败时，手改和顶栏按钮仍可用，对话区显示助手未就绪。

## 落成项目

顶栏按钮，先出确认框。只带走所选剧本沿连线可达的节点。有多条剧本时必须选一条。没有剧本但有分镜时，按镜号写入第 1 集，剧本正文为空。确认框列出角色、场景、道具、分镜数量，以及有文件的图、视频、配音和是否有成片。

第一次新建一部剧，标题用画布标题，比例写入剧 metadata，并记下 `materialized_drama_id`。剧风格用连到这条链路的风格节点，多条时按节点 id 升序用逗号拼成一段，没有则留空。

| 节点 | 写入 |
|------|------|
| 剧本 | 第 1 集标题与 `script_content`。用单行更新，不调用会软删除其他集的保存函数 |
| 角色 | 该剧角色的名字、外形提示词、图片地址 |
| 场景 | 地点名、提示词、图片地址 |
| 道具 | 名字、提示词、图片地址 |
| 分镜 | 镜号、动作、台词、时长、`image_prompt`、`video_prompt`。`context_for` 的场景写入 `scene_id`，角色写入该镜角色列表 |
| 图片、视频、配音 | 不重新生成。文件若不在该剧目录，先复制进该剧存储再把地址挂到分镜；画布节点仍指向原文件。生成记录补上剧 id 和分镜 id |
| 合成 | 不重新压片。给这一集写一条合成记录，指向复制后的成片文件 |

`failed` 或没有文件的节点只写文字。复制失败的那一镜同样只写文字，结果里说明缺了哪一镜的文件。

整次落成是一个数据库事务。失败则回滚，不留下半部剧，也不写 `materialized_drama_id` 和 `bound_id`。

再次落成更新同一部剧：已有 `bound_id` 的行做单行更新，新节点才插入。从画布拿掉、项目里仍在的角色、场景、道具、分镜列在确认框中，默认不删，勾选后才删。

完成后提供打开该剧列表模式的入口。此后列表和旧画布改剧表，自由画布改文档。项目要跟上画布，再点一次落成。

## 接口

都在现有 `/api/v1` 下。

- `GET /free-canvases`、`POST /free-canvases`：列表和新建空白画布。
- `GET /free-canvases/:id`：读取文档。
- `POST /free-canvases/:id/commands`：人手编辑和智能体共用的命令入口，请求体为命令名、参数、`revision`。
- `POST /free-canvases/:id/upload`：往上传节点写入文件。
- `POST /free-canvas-agent/chat`：SSE。请求体 `{ message, canvasId }`。事件形态与现有剧助手一致，另加 `select` 事件。
- 允许、拒绝：沿用现有审批接口的形态，区分删节点和付费运行。
- `POST /free-canvases/:id/materialize`：请求体包含所选剧本节点 id，以及确认框里勾选的待删除 `bound_id` 列表。

剧助手的工具列表不增加画布命令。画布 id 只从请求上下文取，模型写在参数里的画布 id 忽略。

## 测试

后端 `node --test`，文本模型和生图、生视频、配音换成假实现：

- `apply_ops` 能建成剧本 → 分镜 → 图片。非法连线、成环、第 41 步、改服务端字段，整批不生效。
- revision 不一致时拒绝。
- 未允许的 `delete_nodes` 不删。删除编组后子节点还在。
- 剧本 `generate_text` 和 `split_storyboards` 写回节点。下游已有图片时拒绝拆分。超过 30 镜拒绝且不留节点。
- 出图、出视频、配音在允许前不产生生成记录。允许后才调用服务，剧 id 为空，节点记下任务 id。
- 任务完成把文件地址写回节点；与一次并发的拖拽保存冲突时，地址仍在。
- 图片提示词包含风格词和角色上下文。
- 落成建立剧、集、角色、场景、道具、分镜并挂上已有图片。再次落成更新同一部剧。未勾选时，画布已拿掉的分镜仍在。事务中途失败时，剧和 `materialized_drama_id` 都不留下。文件复制失败时该镜仍有文字、没有图片地址。

前端把纯函数放进 `node --test`：连线是否合法、回执如何合并进文档、助手自然语言不改图、一块画布只有一张确认卡、落成确认框的数量。

实现按四段落地，行为以本文为准：文档与手改，命令与对话，运行，落成。
